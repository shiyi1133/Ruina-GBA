废都物语 GBA 兼容框架：设计与当前边界

目标
读取原作 RPG Maker 2000 的数据库、地图及事件，在 GBA 上执行共用规则。
一次实现一条指令或规则，使所有引用它的原事件复用；不逐章重写剧情、配方、奖励或敌人数值。
首先覆盖废都物语实际需要的 RM2000 行为。尚不承诺运行任意 RM2000/2003 游戏。

三层职责
1. runtime/rm2k/ 共用运行时
   lcf.c：不依赖堆分配的 LCF 读取。只缓存不可变 ROM 字段和数组边界；不缓存变量或事件条件结果。
   commands.bin/pages.bin 只预解码原始传输；开关、变量、物品、队友和计时器条件每次仍实时判断。
   borrowed_commands.c 让短控制指令借用只读操作数，复杂命令仍用自己的参数槽；不缓存指令执行结果。
   state.c：变量、开关、角色、经验、状态、地图/公共事件调用栈。
   interpreter.c：用 liblcf 指令编号解释原事件，调用显示、输入、存档等服务。
   rm2k_rules.c：可独立在主机测试的基础计算；不访问 GBA 寄存器或废都物语地图编号。
   battle.c、inventory.c、equipment.c、field_skills.c、shop.c：共用行为与现阶段小屏菜单。
   item_mask.h 将原本按编号升序的拥有物品列表暂存为位集；买入清单保留调用者的顺序和重复项。
   物品和商店界面按变化行/数量更新；复杂换行名称保持原完整绘制，显示优化不改价格、消耗或筛选条件。
   timers.c：原作定时器。parallel.c：独立栈的合作式并行解释器。
   map_rules.c：事件位置、朝向、地形及通行查询。movement.c：强制移动路线。
   world.c：实际步行、调查点寻路与地图绘制。探索地图采用 1:1 原尺寸视野与图块环形缓存；
   滚动只补入新边缘，角色、地点标记、小型 HUD 与三角箭头交给 OBJ。
   地形/图片/色调变化更新脏区；文本菜单保留地图 VRAM，切图、RGB 位图或保存借用缓冲后按需重建。
   镜头移动只读取渲染快照，不重复执行事件页解析；人物的图集、索引、朝向和图层打包进既有快照。
   开关、变量、物品、队伍、朝向/通行、计时器及图像改变时失效显示快照；事件解释器仍实时判断原条件。
   LCF 原 320×240 屏幕坐标查询保持不变，GBA 原尺寸视野使用独立投影，不改剧情变量。
   types.h/audio.h/engine.h 声明服务接口。战斗等菜单仍含当前小屏布局，不是完整的跨平台 UI 库。

2. platform/gba/ GBA 后端
   ARM7 启动/链接、帧缓冲、字形、实体按键、音频硬件和 SRAM。
   dialog.c/event_input.c 把原文字、选项、取名、数字输入映射到小屏；不替换原剧情选择的结果。
   video.c：探索地图用 Mode 0 BG0；文本窗口使用独立 4bpp BG1，插图和战斗为 Mode 3 RGB555。
   BG0 缓存 32×24 个 8bpp 图块，48 KiB；screenblock 30 为 32×32 环形屏幕表。
   BG1 图块占 [0xc000,0xf000)，384 个去重图块；screenblock 31 为文字屏幕表。
   文本 CPU 表面仅 19200 字节，与 RGB555/地图/BFS/存档暂存共用 76800 字节缓冲。
   BG1 关闭时恢复原 BG0 和对象；普通文字菜单不覆盖背景缓存。
   UI 超过 384 个不同图块时退回 RGB555，按软件相机影子读取地图，不能回读只写 HOFS/VOFS。
   地图 OAM 使用符合硬件步幅的 1024 字节影子表，保留旧列表，在 VBlank 用 DMA 与镜头偏移一起提交。
   人物纹理槽按内容复用，优先使用上一画面未引用的槽；不因可见对象排序而全部重新上传。
   长距离镜头移动分解为最多 16px 横向、32px 纵向的安全步幅，不覆盖旧视野正在引用的背景槽。
   绘制底图和地图附着图片时使用当前分段的实际渲染相机，防止目标坐标提前污染缓存。
   最多 48 个地图角色用 8bpp OBJ，24 个内容纹理槽；按当前姿势所用颜色分配调色板。
   旧颜色占满后重建当前可见对象的映射；尚显示的纹理保留到新列表提交，HUD 图像也延迟上传。
   UI 标记保留前 16 色；人物和两套小型 HUD 共用其余颜色，超过容量才近似。
   需要覆盖仍在显示的纹理槽时，先写 CPU framebuffer 的 4096+slot×1024 区域，
   两个 HUD 只写前 4096 字节。最后在 VBlank 一并上传纹理、调色板和 OAM。
   背景上传必须先于这些暂存；暂存到提交之间禁止重用整屏缓冲作 BFS 或其它绘制。
   提交后导航可重新借用该缓冲，不额外申请 24 KiB 常驻 RAM。
   颜色查找缓存限制探测次数，缓存未命中仍执行同一精确/最近颜色计算，避免满缓存后逐像素扫描 512 槽。
   原始 48×48 对话头像使用各自原 RGB555 调色板绘入 CPU 表面，不合并多组头像颜色。
   RGB/原生地图模式切换管理显存所有权；地图文本叠层暂存并恢复占用的对象纹理和调色板。
   菜单/画廊不使用探索地图滚动；原 SELECT 子菜单保留，R+方向键专用于浏览视野。
   image.c 直接采样预转换素材的物理行列，局部重画不展开无关像素。
   编码 6 为独立 8×8 无损 LZ4 图块，共享重复内容；编码 7 为精确的单色图像。
   旧 CharSet 兼容后备仍有编码 4，实际地图人物从完整 24×32 角色库读取。
   原尺寸 8×8 图块和 1:1 不透明裁剪有直接复制路径；与原素材逐像素对照。
   对齐的不透明原尺寸底图通过 image_storage_tile 借用完整 8×8 解码块，复制后才调用下一次解码。
   RGB 图像使用 rgb_surface.inc 的原尺寸/双线性采样、色调和预乘透明；脏行最终与 VRAM 比较。
   Mode 3 切换按黑屏硬切处理；已经在 Mode 3 时只提交实际改变的扫描行范围。
   GBA 寄存器集中于后端；本作启动适配仅读取硬件状态作为随机种子。
   音频使用 16384 Hz 事件时钟、128 路简化合成与 2048 帧 EWRAM 队列（125 毫秒）；绘图补充点使用全部队列余量。
   MIDI 游戏音色单声道，欣赏音色立体声，原事件/控制器/循环不因音色简化重写。
   六首 WAV 共用转换录音，保持各自原单/立体声布局与循环，不受合成质量开关影响。
   音效混合按小块提取固定参数，硬件 IRQ 不逐样本反复解析资源表。
   图形的颜色映射、图标初始化、HUD 解码、地图事件索引和绘制快照都有声音补充点。
   存档 codec 提供可选的 packet-boundary 服务回调；GBA 的压缩/解压、校验和 SRAM 读写补充音频。
   普通 codec 接口及编码字节不变，回调不改写存档源状态，硬件寄存器仍仅由后端访问。
   VBlank 串号允许完成显示后直接消费已到来的逻辑帧，避免额外等待第二次 VBlank。

3. source/ 废都物语适配
   game_profile.h 定义本游戏数据容量与存档身份；编译期检查位集和 SRAM 容量。
   ruina_adapter.c 处理开场、原图片与头像显示、背景和章节提示。
   maps.c 提供系统菜单；调查点交互在共用 world.c 中，不重写事件开放条件。
   source_menus.c 把原料理、锻造、制甲、调和、称号等图片式菜单映射为列表。
   tools/source_menu_assets.py 从原事件提取列表名称并保留来源；选中后仍调用原地图事件。
   配方、SP/证书消耗、技能授予、失败分支都留在原事件中。菜单存在不等于全部内容已完成验收。

原数据与资源
build/original_lcf.bin 保留原包 73 份 LCF 文件，运行时直接读；build/original/ 是工具使用的原始单文件副本。
图像和字形预转换为 GBA 可显示数据；音乐/音效预转换为 GBA 可播放数据，原 LCF 不因转换而改写。
容量通过 game_profile.h 配置，静态数组用于控制 GBA RAM 使用；不能任意扩大后就视为支持其它游戏。
新资源或配置改变后必须重新构建并核对 RAM、ROM 和存档布局。

上游实现与复核
third_party/sources.lock.json 固定 EasyRPG Player 0.8.1.1、liblcf 0.8.1 的提交和文件哈希。
这些是有署名和许可证的参考/适配来源，不是把整个 EasyRPG 直接链接到 GBA。
rm2k_commands.h 由所锁定的 liblcf 枚举整理，审计脚本检查编号完全对应。
tools/check_rule_parity.py 提取所锁定上游的真实函数，在主机编译对照：经验曲线、普通攻击/技能基础值、MP 消耗、防御、浮动及变量运算。
该对照不是原 RPG_RT.exe 执行，也不替代模拟器剧情/战斗和实机测试。

覆盖清单与扩展方法
tools/audit_compatibility.py 扫描全游戏地图、公共事件、战斗事件，输出 evidence/refactor/compatibility_audit.json。
该清单区分“未实现”“部分支持”“画面适配”和“存在实现但运行验收另计”；不能按指令出现次数当通关率。
补一项兼容行为时，先核对固定上游的参数与边界，在共用层实现；增加有意义的规则对照或原事件按键验证，再检查引用它的已有路线。
不要用发送虚假战斗胜利、添加材料、改写开关或直接推进剧情来替代缺失行为。

当前开发与未完成内容
完整自然流程尚未验收。本轮按用户授权持续优化画质和性能，准备 v0.7 均衡画质可玩版供评估。
战斗事件、并行调度、定时器、模拟攻击、地形与强制移动已有实现及分项测试。
指定原事件的主机受控测试不等于在游戏中自然走到所有后期事件。
独立 GBA 容量测试可以验证十敌人菜单，但不计作自然打通该场后期战斗。
仍需补齐或验收：
- 已有步行、接触机关、通用图片和路径查询的实现及分项抽查；后期自然流程仍需玩家验收。
- 已抽查手册、世界地图、武器和防具制作；不能据此称全部特殊界面和全部配方均已验收。
- 状态、装备组合、技能和后期战斗仍需要结合实际流程抽查或玩家反馈。
- 音色按用户要求简化。本轮 105 首配乐在两种音色下共 210 项 GBA 整曲检查通过；有循环的覆盖初次播放及一次完整重复。音乐欣赏另有 128 次循环的持续播放抽查，以本轮哈希绑定报告为准。
- 原作本包所有地图事件页的自主移动类型均为静止；未据此承诺其它游戏的自主移动类型。
- 后续状态扩大仍需复核压缩存档容量；当前 Game 为 39704 字节，写入 32 KiB SRAM 前检查容量。
遇到未支持的实质指令会停止并报告；未到达或未测试的内容保持未完成状态。

验证等级
原数据逐字节/解析核对、主机规则对照、mGBA 实际输入流程、原 RPG_RT 对照和 GBA 实机是不同结果。
已发布 v0.2 以其 acceptance_receipt.json 中的 ROM 哈希及每份报告为准。
机制覆盖的历史记录见 evidence/mechanisms/functional_status.json；当前 v0.7 画质、性能与抽查汇总见 evidence/balanced_optimization_20261023/final_acceptance.json。保留旧失败/拒绝/未运行证据。
开发版写入 v5，读取 v2/v3/v4/v5；状态压缩、校验，超出容量拒绝写入。
v2 事件字节标记迁为位集。不读取 PC 原版存档或模拟器即时存档。
原作并行事件的调用栈在普通读档后重新启动；变量、开关、定时器和强制移动状态另行保存。
首个 CP 后“继续”用于访问现有探索与菜单，不表示后续全游戏已验收。

v0.7 战斗菜单增量恢复：
choices_selected 与 inventory_select_from 保存上级光标。actor_plan 仅在目标确认后提交行动；
角色指令取消清除临时行动并恢复行动选择前 RNG，防止取消菜单改变自动角色的随机规划。
背景恢复只覆盖旧窗口中新露出的区域；角色焦点单独刷新顶部名字。
Mode 3 的未显示显存 0x06012C00–0x06017CFF 存放 144×72 RGB555 背景片段。
缓存由 battle_background_stamp 与 balanced_surface_epoch 绑定；非菜单 draw_scene 会使其失效。
该区域与地图/头像资源分时使用，保留 0x06017F00 的光标图块；地图返回由现有重新上传机制恢复。
整图和片段均使用原颜色，不增加新的减色。RGB 填充用对齐的 32 位成组写入；
画面提交仍在 VBlank 完成，分批 DMA 上限 256 字，避免大量微小 DMA 启动开销挤出 VBlank。
check_battle_menu_comparison 以原普通 SAV 对照完整重绘的 48 个画面与取消后的资源，
measure_balanced_battle 另走法师新游戏并六次往返技能目标，按硬件帧检查完整画面。


v0.7.4 动画优化
- 运行时 Game/SAV 布局不变；动画播放偏好是本次运行的临时设置。
- 原速模式以硬件 VBlank 时钟推进战斗动画，逐帧模式沿用每次引擎更新推进一格。手动暂停的验证夹具仍逐帧绘制。
- 过期过渡图案可以省略，所有到期 timing 记录按原始时间与数组顺序处理一次。每段结束保留末帧并还原干净场景。
- 静态战场图案与动态回合/HP/MP 条带分开缓存；死亡、隐藏、变身、场景切换和其它 VRAM 占用使缓存失效。
- 模态菜单复用已存在的动画静态图案。缓存不足时回到裁剪源图绘制，颜色不做额外量化。
- GNU ld OVERLAY：背景准备代码暂借 3040 字节绘制工作行；编码器与恢复器共享另一指令槽。所有覆盖代码均从 ROM 显式加载后调用，音频 IRQ 使用独立代码/数据。
- 场景颜色索引表使用 SP32 行去重/游程编码，逐项映射不变。预合成动画帧保存 RGB555 色卡、透明区域、矩形或索引行跨度。
- 游戏音乐以四个硬件样本为一组更新合成值；欣赏细致档保留原有自适应采样，通常为两个。事件时钟和音符相位按原样本数推进。
